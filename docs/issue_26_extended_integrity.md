# Issue #26 Extended Integrity Regression

## Scope

Branch `issue-26-extended-integrity` starts at v0.7.0-alpha1 (`df66f3f`).
This is a Home Assistant protocol/learning fix. No radio-band configuration,
LilyGO C++, RF timing, legacy integrity algorithm, or thermostat TX behavior
changes. Hardware acceptance still requires reporter testing.

## Cause And Correction

The previous extended algorithm used final XORs `0x23/0x65`. Those are the
reduced serial contributions for Alex's `08E905`, not universal constants.
Using the full alternating lanes includes the identifier:

```text
T(x) = build_err_byte(x, 0, 0)
lane(values): start at 0; for each value, accumulator = T(accumulator XOR value)
W9  = lane(W1, W3, W5, W7)
W10 = lane(W2, W4, W6, W8)
```

Both RX validation and TX generation use this construction. The low-level
reduced-lane helper remains available for historical analysis; its Alex-specific
tests remain valid.

Two associated capture-backed problems are addressed:

- Preserve learned fixed W4 bits using mask `0x8C`, not only bit 7. Willy's
  manual frames contain bit 2; stripping it would change generated commands.
  Its meaning is not assumed. Learning rejects inconsistent fixed flags.
- Accept observed extended flame-zero states without rewriting the power bit.
  Zero may indicate shutdown or, in thermostat mode, flame-only shutdown.
  These observations do not enable HA flame-zero/thermostat TX or loosen legacy
  state validation.

Existing Alex templates containing `w4_base=0x80` remain compatible. No profile
migration is required for those profiles. A profile learned with missing fixed
bits cannot recover them automatically and should be relearned.

Recommendation: retain every available distinct state and replay raw repeated
captures too. This corpus is small and fast, so sampling it down adds no useful
savings. Integrity expectations are recorded bytes, not outputs generated by
the new formula. Legacy decoded captures are not represented as raw PCM.

The confirmed 433.92 MHz remote from Issue #21 has no saved packet capture in
this corpus. A labeled YardStick capture can fill the protocol evidence gap;
it cannot establish LilyGO hardware reception. Do not count a synthetic remote
ID or frequency-selection test as a real capture from that remote.

## Tests And Red/Green Evidence

Tests were added before changing production code. On unchanged v0.7.0-alpha1,
the initial corpus plus existing Issue #15/ECC tests produced **113 failures,
425 passes**. All 29 Willy rows failed integrity and raw replay. Existing Alex
raw replay and both legacy remotes passed. Additional failures exposed ignored
serial corruption, lost fixed W4 flags, and one Alex flame-zero observation.

After the production fix, the exact initial selection passed **538 tests**.
Additional regressions cover inconsistent learned flags and manual/thermostat
flame-zero observations without changing their power bits.

Coverage includes:

- All 120 valid extended capture rows: recorded integrity, raw PCM replay,
  semantic RX and, where supported, byte-for-byte manual TX reconstruction.
- Explicit rejection of unsupported HA TX for thermostat or powered flame-zero
  observations, plus continued rejection of manual legacy powered flame zero.
- Every single-bit mutation of all ten words for both extended identifiers
  (160 cases), including all three serial bytes.
- Legacy decoded RX/TX, captured C/D derivation, and corrupted error rejection.
- Guided learning of Willy's fixed template fields and inconsistent-flag
  rejection. Existing learning/control tests also remain in the test suite.
