# Proflame2 Setup Guide

Use this guide when adding a fireplace profile to the Proflame2 Home Assistant
integration.

## Overall Setup Flow

1. Install the Proflame2 integration.
2. Prepare the controller that will control the fireplace:
   - LilyGO T-Embed CC1101, or
   - YardStick One.
3. Open Settings -> Devices & services -> Proflame 2 Fireplace.
4. Select `Add entry`.
5. Choose how Home Assistant should learn or receive the remote profile values.
6. Select the fireplace features your installation supports, then review optional settings and save.
7. Validate basic controls from Home Assistant.

The controller you choose is the device Home Assistant will use to control the
fireplace after setup. The learning option controls how Home Assistant obtains
the original remote profile values during setup.

Each controller must be dedicated to one fireplace. Setup rejects a controller
that is already assigned, even when the new remote has a different Learning ID.
Use another controller, or remove the old fireplace entry before reusing it.
Disabled entries still reserve their controller. If an older installation has
duplicate assignments, only the first enabled entry loads; the other entry shows
a setup error until the conflict is resolved. No profiles are deleted automatically.

## Add Fireplace Profile

When you first add the Proflame2 integration, Home Assistant asks which setup
path to use.

- `Learn from remote (Recommended)`: normal setup. This uses the selected
  LilyGO or YardStick controller to listen while you press buttons on the
  original fireplace remote. Most users should choose this option.
- `Enter a Learning ID`: use an ID generated by the companion helper or copied from an
  existing Proflame2 fireplace in Home Assistant. Supports both legacy and
  extended remotes. See [Using Learning IDs](#Using_learning_ids).
- `Enter legacy values`: use older records containing a remote ID and C/D
  values. This option supports legacy remotes only.

## Learn Fireplace Profile

This is the normal `Learn from remote` setup path and is recommended for most
users.

Use this when you have a supported Proflame2 controller ready:

- LilyGO T-Embed CC1101, or
- YardStick One.

**Fireplace name** is the name Home Assistant shows for the fireplace device and
its entities. Use a name that clearly identifies the fireplace, such as `Living
Room Fireplace` or `Basement Fireplace`.

**Display short name** is the short name shown on a supported Proflame2 controller
display. It is intended for small screens where the full Home Assistant device
name may not fit. Use a short label that is easy to recognize at a glance, such
as `LIVING`, `DEN`, or `BASEMENT`.

**Controller Type** is the device Home Assistant will use to control the fireplace
after setup. Choose `LilyGO T-Embed CC1101` if you are using the LilyGO
controller firmware. Choose `YardStick One` if you are using a YardStick
controller.

After controller selection, YardStick asks for the RF band (315 or 433 MHz);
LilyGO asks for its ESPHome device. Home Assistant then starts listening with
the selected controller and walks you through a short sequence of original-remote button
presses. Start with the fireplace turned off so each prompted button press
matches what Home Assistant expects.

When learning completes, the same controller is used to control the fireplace.

**If you choose YardStick One**

315 MHz is the default for most users. Check the label on the back of your
original remote or inside its battery cover. Select 433 MHz if the label or
model-specific documentation specifies 433/433.92 MHz. If the frequency is not
printed, use the model/part number to check the remote or fireplace manual;
digits in an FCC ID do not directly identify the frequency. See the
[YardStick radio band guide](yardstick_controller.md#radio-band) for details.

Learning starts only after you submit the band choice. Home Assistant creates
one fireplace device; there is no separate YardStick device. Later band changes
are available under RF band in the fireplace device's Configuration section.

YardStick uses the same learning procedure for legacy and extended remotes.
Turn OFF thermostat and SMART mode before starting. If either mode is detected
on an extended remote, learning asks you to turn it off and then continues
automatically. Room temperature, setpoint, or temperature-unit changes do not
require restarting learning.

**If you choose LilyGO T-Embed CC1101**

If you choose `LilyGO T-Embed CC1101`, Home Assistant will also ask you to choose
the LilyGO ESPHome device before learning starts. Home Assistant needs this so it
knows which ESPHome device should listen for the original remote.

Select the ESPHome device that is running the Proflame2 LilyGO firmware.

If the device is not listed, add the LilyGO controller to Home Assistant through
the ESPHome integration first, then return to Proflame2 setup. See the
[LilyGO CC1101 controller guide](lilygo_cc1101_controller.md) for setup
instructions.

## Select Supported Features

Setup ends with two pages: **Fireplace features** and **Optional settings**.
Choose the supported features first, then review optional settings and submit to
save. Closing either page cancels without saving. The same two pages are used
when editing fireplace settings.

Individual fireplaces do not support every Proflame2 feature. Enable only the
features your fireplace actually has. These choices control which Home Assistant
entities are created for the fireplace.

Available feature choices:

- `Fan supported`: enable fan speed controls.
- `Light supported`: enable accent light controls.
- `Front burner supported`: enable front burner controls for fireplaces that
  have a separately controlled front burner.
- `Aux supported`: enable auxiliary controls for fireplaces that have an
  auxiliary output.
- `CPI (Continuous Pilot Ignition) supported`: enable the pilot-mode control
  if your fireplace supports selecting CPI and IPI.

### CPI and IPI Pilot Modes

The **CPI** control selects how the pilot operates between uses of the main
burner:

| CPI setting | Pilot mode | Behavior | Why use it? |
| --- | --- | --- | --- |
| **ON** (`1` or `true`) | **Continuous Pilot Ignition (CPI)** | Keeps the pilot lit between uses, subject to the fireplace's automatic shutoff features. | Keeps the firebox and vent warmer, helping establish draft and reducing ignition difficulties in cold or damp weather. |
| **OFF** (`0` or `false`) | **Intermittent Pilot Ignition (IPI)** | Lights the pilot when needed and extinguishes it between uses. | Reduces gas consumption and unwanted heat, particularly in warmer months. |

Turning **CPI OFF** selects IPI; it does not disable the fireplace's ability to
light its pilot when needed. The CPI setting is separate from main-burner power,
so selecting CPI can keep the pilot lit while the fireplace's **Power** control
is OFF. The control indicates the selected mode, not confirmation that a pilot
flame is physically lit.

Follow your fireplace model's manual when choosing a mode. See
[Regency's explanation of CPI, IPI, and cold-weather starting](https://www.regency-fire.com/en/Owners/Service-Maintenance/Fireplace-Care-Guides/Your-Electronic-Ignition-Appliances-and-Cold-Start)
for manufacturer guidance on these tradeoffs.

### Optional Settings

- `Allow flame OFF while power is ON`: enable only if your original remote
  can turn the burner off while leaving the fireplace ON for lights or fan
  operation. It is disabled by default. When enabled, Flame can be set to 0;
  subsequent accessory adjustments keep the burner off. Power OFF preserves the
  flame setting. Turning power from OFF to ON starts at the retained level,
  using level 1 if it was 0. An explicit service/profile flame value takes
  precedence. Sending Power ON again while already ON keeps flame 0.
- `Refresh period in minutes`: send the current fireplace settings again after
  this many minutes without a command being sent or heard from the original
  remote. The default `0` turns this off. Reminders are sent only while Home
  Assistant shows the fireplace as ON. Use this only if your fireplace needs
  regular reminders to stay on.
  See [Optional inactivity refresh](../README.md#optional-inactivity-refresh)
  for the reported ten-minute setting and native-remote battery requirements.
- `Enable packet debug log`: record detailed diagnostic information for
  troubleshooting. Leave this off unless requested for support.
- `Enable active listening`: update Home Assistant when you use the original
  remote by keeping the radio in listening mode when not transmitting. This
  option appears only for controllers that support active listening.

The display short name is entered earlier during setup. You can edit it later
on **Optional settings**.

For flame-zero support, update both the integration and LilyGO firmware to a
release containing the Issue #33 fix. Older firmware may miss remote-driven
updates in that state. YardStick users need only the integration update.

To disable flame-zero support, first turn power OFF or choose a positive flame,
and edit or delete any saved profiles that use power ON with flame 0. Physical
fan and pilot behavior remains controlled by your fireplace.

For support captures, enable **Debug logging** from the Proflame2 integration's
three-dot menu. The log automatically includes the integration version and, for
LilyGO, its reported Proflame2 firmware version when available. This is separate
from **Enable packet debug log** above and **PCM Payload Logging** on the device.

## Manual Fireplace Profile

Manual entry is not a normal setup path. Use it only when you already know the
exact remote profile values from prior troubleshooting.

In almost all situations, use `Learn from remote` first. If that fails, use
[Enter a Learning ID](#Using_learning_ids). Select **Enter legacy values** only
when your existing records contain a remote ID and C/D values instead of a Learning ID.

## Using Learning IDs

A Learning ID lets you set up a specific native remote without repeating the
learning process. It supports both legacy and extended remotes. You can obtain
one in either of these ways:

- **From an existing HA fireplace:** open its Proflame2 device in Home Assistant
  and copy **Learning ID** from the Diagnostic section.
- **Using the companion Learning ID helper:** run the source-only Python archive
  on Linux/macOS with your own SDR and compatible rtl_433 installation. The
  helper guides you through remote button presses and generates the ID. See
  [helper download and instructions](Using_rtl_433_for_learning.md).

Home Assistant accepts the resulting Learning ID, not rtl_433 output. There is
no separate receiver/JSON-paste setup option. The helper runs outside Home Assistant;
your LilyGO or YardStick remains the controller used after setup.

### Save Your Learning ID

Once generated, save the complete Learning ID with your fireplace records and
label it with the native remote it belongs to. It continues to describe that
specific remote, even if you remove the HA fireplace entry, reinstall the
integration, or replace the controller. It is not a shared code for every remote
with the same model number. A replacement native remote needs its own ID.

The ID contains only the information needed to identify and learn the remote.
It does not contain your fireplace's enabled-feature choices. Changing those
choices in HA does not change the ID, and you do not need to save it again.

### Import a Learning ID

Choose **Enter a Learning ID** when adding a fireplace profile, paste the complete value,
and provide the name and controller for this installation. For LilyGO, select
the ESPHome controller in the next step. Then choose which fireplace features
to enable on the **Fireplace features** page, followed by **Optional settings**.

The ID restores the remote's identity, protocol, and learned transmit values.
You select supported features during setup and can adjust them afterward using
**Edit fireplace settings**. The ID does not copy the current fireplace settings,
controller connection, or radio band.
Make sure the LilyGO is configured for the original remote's frequency.

Learning IDs contain enough information to reproduce commands for that remote;
do not publish them without considering that exposure. They identify a particular
remote, not every remote with the same model number.

### Enter Legacy Values Instead

If you have older remote ID and C/D records instead, choose **Enter legacy
values** in the setup menu. This alternative requires:

- `Remote ID`
- `C1`
- `D1`
- `C2`
- `D2`

Most users will not know these values. Neither manual option listens to a remote
or runs rtl_433. See [Learning ID encoding](learning_id_encoding.md) for the
technical exchange format.

## Changing Controls

You can continue adjusting controls while a command is being sent. Home Assistant
keeps your latest combined settings and sends them after the current command
finishes and the normal short delay has expired. Intermediate settings are not
queued for later playback.

If a send fails or the controller disconnects, the controls return to the last
accepted settings. Reconnecting does not automatically resend discarded changes.
A successful send means the controller finished transmitting; the fireplace does
not send an acknowledgement. Check the fireplace itself when troubleshooting.
