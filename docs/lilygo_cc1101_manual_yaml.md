# Manual LilyGO YAML Setup

Most users should use the
[LilyGO YAML helper](https://jeffgregx2.github.io/HACS-Proflame2/tools/lilygo-yaml-helper.html). This page is for manual
setup or troubleshooting when you want to edit the ESPHome YAML yourself.

## Manual Overlay

The manual overlay is here:
[lilygo_cc1101_overlay.yaml](../esphome/examples/lilygo_cc1101_overlay.yaml).

Do not copy the overlay over a blank YAML file. Start with the YAML generated by
ESPHome Builder so your local Wi-Fi, API encryption key, OTA password, and
device identity remain intact.

## What To Merge

After ESPHome Builder creates the device YAML:

1. Keep the generated `esphome`, `wifi`, `api`, `ota`, and `logger` sections.
2. Ensure there is only one top-level `substitutions` section.
3. Add `proflame2_package_ref: "main"` to `substitutions`.
4. Ensure `esp32.framework.type` is `esp-idf`.
5. Add the Proflame2 package entries from the overlay to the existing
   `packages` section, or create that section if it does not exist.
6. Add the restart switch from the overlay only if your YAML does not already
   have a `platform: restart` switch.

Do not copy the repository `esphome/components` directory into your ESPHome
configuration. The package downloads the Proflame2 ESPHome component from
GitHub using `proflame2_package_ref`.

## ESP-IDF Migration

Use ESP-IDF so ESPHome can retain a supported panic backtrace and report it
after a restart, including through network logs. If an existing device uses
Arduino, change only the framework type, keeping the board and other device
settings unchanged, then rebuild and install the firmware:

```yaml
esp32:
  board: esp32-s3-devkitc-1
  framework:
    type: esp-idf
```

Changing the Proflame2 package reference does not migrate an existing device
from Arduino to ESP-IDF. Edit the framework type in the device YAML explicitly.
When using prerelease firmware with the public YAML helper, also check this
setting: the published helper follows stable `main`, not the selected package
reference.

Crash reporting depends on the ESPHome version and build configuration; it is
not a guarantee that every reset will produce a backtrace. During crash
investigations, preserve the `firmware.elf` from the exact installed build before
rebuilding. A different build's ELF cannot reliably decode the crash addresses.

## Package Reference

The `proflame2_package_ref` value tells ESPHome which version of the LilyGO
firmware configuration to download from GitHub.

The default is:

```yaml
proflame2_package_ref: "main"
```

This uses the latest repository version when you rebuild the LilyGO firmware.

Advanced users may pin this to a release tag such as `"v0.3.0"` for
reproducible firmware builds. If you pin a release tag, update it whenever you
upgrade the Proflame2 integration and rebuild the LilyGO firmware.
